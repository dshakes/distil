Task-level A/B

Every other savings number distil prints is per request: tokens removed from what was sent. That cannot tell you what a task cost, and it cannot survive a model change. distil ab can. It compares sessions distil compressed with sessions it deliberately left alone, chosen at random, running at the same time, on the same model.

Why per-request savings are not enough

A new model version changes how an agent works. It may take more turns to finish the same task, or fewer. It may read more files, or cache differently. All of that moves your bill, and none of it is distil. If you compare last month with this month, the model change lands in the comparison as if distil had caused it. In the simulation behind this page, a model that needs about 40% more turns per task makes a before/after comparison of the distil sessions read 40% more cost, while distil was saving 20% the whole time.

The only comparison a model change cannot contaminate is one where both sides see the change at once. So distil holds out a small random share of sessions and compares each group only with the other, at the same time, on the same model.

The holdout

  • Which sessions. Each new distil wrap session is assigned to distil or holdout when it starts. The default holdout rate is 5%. The draw is a keyed hash of the session id with a secret that never leaves your machine. It is deterministic, so a resumed or nested session keeps its arm, and nobody can predict or steer it. It is not the census id, so turning the census off does not re-draw anyone.
  • What a holdout session gets. Exactly what the agent sent. The request goes upstream as the original bytes: no compression, no output shaping, no expand tool, no cold-point, no prefix replay. That is always safe, because it is the traffic you would have sent without distil. It is safe on a subscription too.
  • What is recorded. The same content-free per-request record as always, tagged arm. Holdout requests are not booked as savings. Each session is also folded into ~/.distil/ab.jsonl, so it outlives the 7-day session sweep. Nothing new is sent anywhere.
  • Turning it off. distil ab --holdout-rate 0, or DISTIL_HOLDOUT_RATE=0. The wrap prints a line on every held-out session, and distil setup states the rate.

What is measured

Per session: dollars (the provider's own usage counts priced at list, cache reads at a tenth and cache writes at 1.25 times the input rate), assistant turns, tasks, input and output tokens, errors, wall time, and how it ended (normal exit, error, or abandoned). A task is the stretch between two things you typed. Distil tells them apart from tool results by the message's role and block types, never its content. Sessions recorded before that marker count as one task.

The headline is the relative change in cost per task, distil against holdout. Beside it are the change in turns per task, which shows whether compression made the agent work harder, and the change in cost per turn.

Staying within one model

Sessions are grouped by the model that carried most of their cost and by the client and its version (for example claude-cli/2.1). When a newer version of the same model family appears, it supersedes the old one. The headline then compares within the new model only, and the report says so: model changed on 2026-08-05: comparing within the new model only. The old model's result is kept, and the two are compared as a difference-in-differences: distil's effect after the rollout minus its effect before it. That is the question a rollout actually raises.

A model can also change behind an unchanged id. Distil watches cost per task for a sustained shift, and when one is detected it starts a new era and compares within that era. Estimates never mix eras.

The part that actually protects the estimate is the randomisation, not the change detection. Both groups run at the same time, so a model change moves both and cancels in the contrast. Eras exist so that the number describes the model you are running now.

That is a simulated history. Opus changes version on 5 August, and the new version needs about 40% more turns per task in both groups. The headline stays on distil's effect, and the difference-in-differences across the rollout is indistinguishable from zero, because distil's effect did not change. Below the minimum data, the report says not enough data yet, gives the sessions so far, and estimates how many more it needs.

Cost of the holdout is what the held-out sessions would have saved had they been compressed. It is the price of knowing. At the default rate, and assuming a session's cost typically varies by about as much as its mean, resolving a 10% effect takes about 27,740 sessions and a 20% effect about 7,240. That spread is an assumption, not a measurement of real traffic; once there is data, the need ≈ figure in the report is sized from your own sessions. A larger holdout gets there sooner and costs more.

The math

The estimate

The session is the unit, because it is what was randomised. For a ratio metric such as cost per task, each group's value is the ratio of its sums, C̄/T̄. The effect is the difference of the two logarithms, Δ = log(C̄₁/T̄₁) − log(C̄₀/T̄₀), and exp(Δ) − 1 is the relative change. Its variance comes from the delta method on each session's linearised contribution Lᵢ = Cᵢ/C̄ − Tᵢ/T̄.

Variance reduction (CUPED)

Much of the spread in session cost is between projects, not between arms. So each session's L is regressed on its workspace's mean cost per task over sessions that ended before it started. Those earlier sessions were assigned independently of this one, so the adjustment cannot bias the contrast. It only removes spread. A session with no history is left unadjusted. In the simulation, where workspaces differ a lot, it cut the variance by 44% and the interval width to 0.75× of what it was.

Anytime-valid intervals

You can run distil ab whenever you like, and so can every screen that shows the result. An ordinary fixed-sample interval checked again and again will eventually exclude zero by chance. In the simulation, checking one after every 20 sessions up to 400 flagged a difference that was not there 27.9% of the time. The interval here is a confidence sequence (the mixture sequential probability ratio test). With V the variance of Δ and a fixed mixing scale τ = 0.2:

e-value  Λ = √(V/(V+τ²)) · exp(τ²Δ² / (2V(V+τ²)))
interval Δ ± √( V(V+τ²)/τ² · log((V+τ²)/(V·α²)) )

By Ville's inequality, the chance that Λ ever reaches 1/α under no effect is at most α, however often it is checked. α is distil's single failure budget, distil.conformal.BUDGET_DELTA, shared with every other statistical claim distil makes. Under the same repeated looks, this interval flagged a non-existent difference 1.3% of the time. The guarantee is asymptotic, since the variance is estimated from the data, which is why there is a data floor. The cost is power at any single look: a true 20% saving at 400 sessions split evenly was detected 46% of the time, and at 800 sessions 92%. A percentile bootstrap is printed beside it as a fixed-sample cross-check.

Pooling

Each model-and-client cell in its current era gives its own Δ. The headline weights them by inverse variance, so it is a precision-weighted average effect, not a traffic-weighted one.

Detecting a silent change

A two-sided self-starting CUSUM runs on log cost per task. Each session is standardised by the mean and spread of the sessions before it in the same era (k = 0.5, h = 12). It reads both groups together, without looking at which is which. A new era starts at the first session after the alarm, because data after an alarm never informed the decision. The sessions between the estimated change and the alarm are dropped from both groups. With a model change hidden behind an unchanged id, the headline's bias was +0.5 points (±0.4); with an explicit version change it was +0.1 (±0.4). A silent change the detector misses only leaves two regimes averaged together; the comparison within them is still randomised. Any detector selects the data it cuts on. Measured at h = 8, where false eras are common enough to measure, eras closed by an alarm on the holdout group alone were biased by 6.7 points; read blind to arm, by 1.3 points. That is why it reads both groups, and why no difference-in-differences is ever taken across one of its eras.

What it does not do

  • Only distil wrap sessions are randomised. A managed install that runs distil proxy from a launch agent has no session to assign, so it is not in the experiment.
  • Models distil cannot price, such as non-Claude upstreams, are counted but not estimated.
  • When a streamed response ran a distil_expand re-query, only the first request's input usage is recorded. The distil group's cost is then a lower bound. The report counts those requests.
  • On a subscription the dollars are list price, not what you are billed. The report marks them as notional.
  • Real session costs drift with your work. Some of that drift will open an era. That costs data, never validity.

Every measured number on this page is reproduced offline by benchmarks/abtest_montecarlo.py into benchmarks/results/abtest-montecarlo.json. The decision record is ADR 0019.
